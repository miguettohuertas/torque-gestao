## Validação

- 88 testes da API aprovados (incluem matriz completa das 25 transições, orçamento,
  snapshot dos preços, quantidades inválidas, autorização e concorrência).
- 7 testes do cliente HTTP aprovados.
- Lint Python e verificação de whitespace aprovados.
- Fluxo Playwright aprovado usando a API real com PostgreSQL: login inválido/válido,
  cadastro de cliente e veículo, dashboard, emissão de OS de R$ 191,00, todas as
  etapas até Entregue, cinco registros de histórico, recarga da aplicação,
  leitura no portal e sessão expirada.
- O teste PostgreSQL cria um schema temporário exclusivo da execução. Os cadastros
  da aplicação permanecem no schema `public`. O schema de teste é removido no
  encerramento normal do servidor.

## Roteiro para apresentar

1. Subir Docker, aplicar migrations e seed, e servir o front-end conforme
   [o guia de execução](../../apps/prototype/README.md).
2. Entrar como administrador e mostrar o painel com números reais.
3. Cadastrar cliente e veículo; abrir OS com serviço e peça do catálogo.
4. Mostrar orçamento e avançar o status; recarregar para demonstrar persistência.
5. Criar acesso ao portal pelo comando documentado, sair e entrar como cliente.
6. Mostrar veículo, acompanhamento e histórico; o cliente não pode alterar o status.
7. Apresentar os resultados de `pytest`, `npm test` e do fluxo Playwright.

A suíte rápida de regras utiliza SQLite. O teste de navegador aceita SQLite
(padrão) ou PostgreSQL; o guia documenta como repetir ambos. A validação feita
nesta entrega é local; execução hospedada no GitHub não é evidência destes testes.
